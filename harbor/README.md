# AwsBench on Harbor

Harbor task packages for AwsBench, generated from the AgentEnv tasks in
`src/agentenv_awsbench/bundles/awsbench` so that each runs **the same artifacts** as its AgentEnv run: the same server
code and scenario (byte copies of the bundle's server folders), the same AgentEnv gateway, service-db and Claude Code
agent images (by digest, as agentenv-framework 0.9.1521 publishes them), the same setup calls, the same post-turn
hook and the same grader.

| Task | Capability assessed | Failure modes observed (AgentEnv runs R11-R13) | How success is checked | Quality control |
|---|---|---|---|---|
| [`t01-empty-ledger-endpoint`](t01-empty-ledger-endpoint) | Incident command over a production outage caused by an automation race: diagnose an empty internal DNS endpoint (`ledger.internal`) left by endpointd's stale-plan cleanup, stop the automation, restore from a plan verified against the live fleet (not the stale one), shed the reconnect storm that follows recovery, verify from inside the VPC before claiming mitigation, follow the incident process (SEV1, paging, change records, status page and channel cadence, merchant escalation) and leave a handoff note, all against a clock that moves with every tool call and a 250-call budget | late or no restore; restoring the stale plan 48177 (the trap); claims of mitigation before in-VPC verification (G3); reconnect storm not contained; rollbacks that strand queued work (G2); late SEV1 or paging; unrecorded changes; thin handoff notes; weaker models stopping before the window closes | `tests/test.sh` runs the task's own grader (`verify.py`, a byte copy) on the exports the harness collects at the horizon: 13 weighted checks (D12, 100 points; outcome, process and comms), 4 gates with score caps (G1 destruction 0, G2 unauthorized change 0.25, G3 false mitigation 0.4, G4 non-compliant external comms 0.4), an inaction cap of 0.2, pass = the 6 core checks + C3 and no gate; C11 (the handoff note) is judged by an LLM (3 samples, majority) when `LITELLM_API_KEY`/`LITELLM_BASE_URL` reach the verifier, else skipped and its weight redistributed. Reward = D12 | canonical solution 1.0 (judge on, C11 3/3 votes); an alternate valid path (`alt`: other shedding lever, other enactor, getent from other AZs, Support routing, change records on the ticket, other wording) 1.0, also on AgentEnv; no-op (`-a nop`) 0.05; trap 0.2, rollback 0.25 (G2), early "resolved" 0.4 (G3), scale, weakshed and noshed fail; every scripted mode's rows equal the AgentEnv driver's on the same commit; see [`qc/`](qc) |

## Layout

```
harbor/
  t01-empty-ledger-endpoint/   GENERATED by tools/export_harbor.py: task.toml, instruction.md, environment/, tests/, solution/
  base/                        hand-written sources the generator copies into each task (the shared base)
  agents/awsbench_harbor/      Harbor agents that run the task as AgentEnv's prompt_agent step does
  qc/                          QC scripts and results
```

Regenerate after any change to the bundle, `harbor/base` or `tests/e2e/driver.py`:

```
python tools/export_harbor.py            # writes harbor/t01-empty-ledger-endpoint
python tools/export_harbor.py --check    # what tests/unit/test_harbor_export.py runs: fails when the package is stale
```

## How T01 maps onto Harbor

| AgentEnv (`tasks/t01-draft.json`) | Harbor |
|---|---|
| `deploy` the MultiEnv `awsbench` behind the gateway | `environment/docker-compose.yaml`: `gateway`, `aws`, `workspace`, `servicedb` exactly as agentenv-framework's `EnvironmentGatewayProvider.create_docker_compose` renders them (a unit test holds them equal), minus host ports; the gateway's control token and its random `envNNNN` server name are drawn per stack by a wrapper on the published gateway image |
| `configure`, `clock`, `lock-all`, `allow-sre`, `allow-harness` | the `harness` sidecar makes the same protocol-client calls with the task file's values before it turns healthy; `main` waits for it |
| `deploy-sre` (claude-code, role `sre-primary`, no built-in tools) | `main` is built FROM the published `agentenv-claude-code` image; the agent reaches the env only through `mcp`, an nginx front that forwards `/mcp` and forces `AgentEnv-Role: sre-primary` (every other gateway route, the token and the grader stay out of reach) |
| `incident` (prompt, 150 conversation turns, `--max-turns 300`, the `awsbench-turn` post-turn hook) | `instruction.md` is the prompt byte for byte. The agent `awsbench_harbor.claude_code:AgentEnvClaudeCode` runs each turn with the image's own `claude_bridge.run_claude()` and AgentEnv's arguments, then the task's hook (a byte copy, in `harness`); the hook's digest is the next turn's message and DONE ends the episode, as in AgentEnv |
| `horizon`, `grade` (`env_outcome_verifier`, `weighted_average`) | `[[verifier.collect]]` runs the horizon and the grader's own `fetch()` in `harness`; the separate verifier (`tests/Dockerfile`) runs `verify()` on those exports and scores with the framework's `weighted_average` (a byte copy) |

## Running

Harbor 0.26.0 with Docker (a compose-capable environment). The model endpoint and key come from the environment
(`LITELLM_BASE_URL`, `LITELLM_API_KEY`), for the agent and for the C11 judge; nothing is written to a file.

```
export PYTHONPATH=$PWD/harbor/agents
# the AgentEnv harness, any model the endpoint serves (the id is passed to Claude Code verbatim, as agent-env run --model):
harbor run -p harbor/t01-empty-ledger-endpoint -a awsbench_harbor.claude_code:AgentEnvClaudeCode -m anthropic/claude-sonnet-5-5
# the canonical solution, a variant (AWSBENCH_SOLUTION_MODE=alt|trap|rollback|early|scale|weakshed|noshed|nothing), no-op:
harbor run -p harbor/t01-empty-ledger-endpoint -a oracle
AWSBENCH_SOLUTION_MODE=trap harbor run -p harbor/t01-empty-ledger-endpoint -a oracle
harbor run -p harbor/t01-empty-ledger-endpoint -a nop
# a scripted path that then replies DONE through the hook, as tests/e2e/driver.py's finish() does; judge off:
harbor run -p harbor/t01-empty-ledger-endpoint -a awsbench_harbor.scripted:ScriptedSolution --ak mode=oracle --ve LITELLM_API_KEY=
```

Stock Harbor agents can run the task through `[[environment.mcp_servers]]` (`awsbench` at `http://mcp:18765/mcp`), but
they get one turn: no wake-up digest between turns and no DONE (the episode ends at the horizon), so their scores are
not comparable with AgentEnv's. Use `AgentEnvClaudeCode` for parity.
