## Methods and caveats

**How the runs were made.** Each run deploys the AwsBench bundle with AgentEnv, arms the gateway clock at the task's
start (02:40 ET for T01, 08:15 ET for T03, 13:12 ET for T04, 10:30 ET for T05), and prompts the solver once with
the page (in T05, the shift handover); a post-turn hook lets up to ten
minutes pass between turns and wakes the agent with what arrived. The solver is Claude Code driving Claude Opus 5.5, Claude
Sonnet 5.5, Claude Haiku 5.5 or Claude Fable 5.2 through a model endpoint, with its built-in tools off: it acts only
through the `aws` and `workspace` MCP tools. GPT-6 Astra runs in the Codex CLI agent (0.147.0, `codex exec`) with the
same tools, at the API's default medium effort, since that Codex has no metadata for the model and sends no effort. T01's budget is 250 tool calls and the 02:40–05:10 window, graded at 05:10; T03's is 220 calls and the
08:15–13:00 window, with the world then fast-forwarded to the 16:15 horizon and graded there; T04's is about 200
calls and 13:12–16:12, T05's 220 calls and 10:30–14:00, each graded at its window's end. The judges (T01's C11 handoff,
T03's C13 root-cause write-up and C18 public text, T04's C12 handoff summary, T05's C12 #sre handover) are one LLM,
Claude Sonnet 5.5 by default, given a fixed fact list.

**What the viewers read.** `tools/export_run.py` turns each run folder into the viewers' JSON: the agent's calls from
the `aws` server's meter and action log, with arguments and results from the agent's session; the world's series
(checkout, ledger-writer load and capacity, webhook backlog, per-host DNS recovery, the ledger record's state, the
dispatcher's concurrency, endpointd's kill switches); colleagues, pages and emails from the timeline and the workspace
records; and the grader's rows. Which checks a call "bears on" is a heuristic over its tool and arguments, not the
grader's attribution. Everything is scrubbed (keys, internal hosts, local paths and endpoints, foreign IPs, account ids
other than the emulator's) and checked before publishing.

**T03's per-host states.** T03's world export keeps the fleet's host counts per minute, not each host's state, and no
export records a host's threads. So `tools/t03_replay.py` replays each T03 run's own calls (the AWS writes, fleet
commands and restarts in its action log, at the times the meter charged them) through the world package as the run's
own build had it, in process,
with in-memory fakes, and samples every host's state, a sample host's threads against its limit and the state of the
scheduled action every 30 s. Each replay is checked against the run's export: its per-minute host counts match the
run's at every minute from 08:15 to 16:15 for every T03 run shown. The stretch from 06:00 to 08:15 is the scenario's
own presimulation, the same in every run.

**The references.** Each task's scripted oracle path from the repository's end-to-end driver, replayed by
`tools/build_hub_data.py` through the world package in process with in-memory AWS and workspace fakes: the same
physics, timeline and colleagues, timed by the same meter, with waits run to their full length. On a deployed env T01's
path grades D12 1.0. T03's outcome checks (C02 to C06, C15) are computed by the grader's own rules on the replayed
world, and so is its runbook check (C16); its other process and communication marks are the ones the path is built to
pass. T04 and T05 have no reference here: their scripted oracles score 1.000 on deployed envs, but those exports were
not kept and neither task has an in-process replay yet. Their runs' viewer data (`tools/export_mech.py`) describes the
world's lanes in the data itself, from each run's exported series.

**Cost.** The cost-and-score plots read each run's solver spend from `hub/run_costs.json`: Claude Code's own
`total_cost_usd` for the session, or for GPT-6 Astra the list price of its token usage in the Codex CLI, as recorded
when the run was made; the judge's calls are not counted. `tools/pareto.py` draws them with the final grader's D12.

**The final grader.** Every run since R8 was graded again offline, from its own exports, by the final grader: T01's at build
<code>{FG.build}</code> (R8 to R10 at 9b076a2, whose later grader fixes move none of them), T03's at 758e202, T04's at
98b9dcd and T05's at b4eb0d9. T01's grader at <code>{FG.build}</code> also credits a change record that names its change in shorthand
(C9: cd49049, then f66efa2 for a value a word or two past the arrow and the verb of a paused flag); of every T01 run
since R8 it moves only five of the six GPT-6 Astra runs, from 0.97 to 1.00. The Claude Sonnet 5.5 runs of R15 were built
at 1633470, whose grader is 689ab3b's, and it moves none of them; those of R16 were built at f79c1db, with this grader. T03's grader is 689ab3b's with its judge on Claude Sonnet 5.5 (758e202), the model T01's judge
uses, so every T03 run's C13 and C18 were judged again once, three samples, with it; no T03 score or pass moved. A T01 judged check keeps its recorded votes when the final grader sends the judge the same prompt; otherwise it is judged again once, three samples, with the final prompt. Only grader changes can move a score this way: world and
colleague fixes can't change what a recorded run did. The results table shows both scores, and each run whose score
moves, or that still loses points, has a note saying why and whose the loss is.

**Caveats.**

- **Development runs.** Runs on older builds met env and grader bugs that the runs themselves found; they are kept for
  what they show. The current runs are on the hardened build: for T01, R11 (six Claude Opus 5.5 runs on 5fe025c)
  and R12 to R14 (six each of Claude Haiku 5.5, Claude Opus 5.5, Claude Fable 5.2 and GPT-6 Astra, on 689ab3b), and
  R15 and R16 (eight Claude Sonnet 5.5 runs each, on 1633470 and f79c1db, slightly later builds of the same task whose
  environment adds the R12 and R13 quality-check fixes); for T03, T03R4, six Claude Opus 5.5 runs on 5fe025c; for
  T04, T04R2, nine runs on 9b8347a (five Opus, two Sonnet, two Haiku); for T05, T05R2, six runs on c9392b8 (four Opus,
  one Sonnet, one Haiku). T04R1 and T05R1 are development runs.
- **Builds.** The R8 and T03R1 run folders' build files were left blank by the run script; the commit shown is the
  branch's head when each run started.
- **Few runs.** Twelve Opus runs of T01 and six of T03 on the current build, six to sixteen runs of each other model,
  and three Opus and two Sonnet runs per earlier build show where a task bites, not a rate. A GPT-6 Astra run costs
  about $12.
- **Calibration.** Every task is easier than its design intends; see Results for the numbers and the reasons.
- **The judges are noisy.** In T01, C11 decides about six points; in T03, C13 and C18 decide twelve; in T04 and T05,
  C12 decides eight and ten. The final grader's
  re-judged rows are single samples of three votes each.
